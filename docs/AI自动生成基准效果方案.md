# AI 自动生成基准效果方案

## 1. 功能概述

### 1.1 目标
通过 AI 根据「未作答的作业图片」（印刷题目，学生未填写）和测试场景，自动生成基准效果（答案文本 + 预期分数 + 填写指导），用户手写填写后拍照，用于系统性测试 AI 批改准确性。

### 1.2 核心价值
- **降低人工成本**：无需人工逐题设计测试用例
- **系统性覆盖**：自动覆盖各类边界场景和易错点
- **可复现测试**：标准化的测试用例便于回归测试
- **精准定位问题**：通过标签快速定位 AI 弱点

### 2.1 核心思路：直接用结构化数据

**不需要图片识别**，直接从数据库 `data_value` 获取完整题目信息：

```
数据来源: zp_homework.data_value (JSON)
├── index: 题号
├── tempIndex: 临时索引
├── content: 题干内容 ⭐ 关键
├── bvalue: 题型 (1单选/2多选/3判断/4填空/5解答)
├── questionType: objective/subjective
├── ans/jans: 标准答案 ⭐ 关键
├── sorce: 分值
└── children: 子题（大题包含小题）
```

**题目提取规则**：
- **只提取小题**，跳过大题本身
- 有 `children` 的是大题 → 只提取 `children` 中的子题
- 没有 `children` 的是独立小题 → 直接提取
- 最终题目数量 = 小题数量

**示例**：
```
原始数据:
├── 第1题 (大题，有3个子题)
│   ├── 1.1 小题
│   ├── 1.2 小题
│   └── 1.3 小题
├── 第2题 (独立小题)
└── 第3题 (独立小题)

提取结果: 5道小题 (1.1, 1.2, 1.3, 2, 3)
```

**优势**：
- **无需图片识别**：题干内容、标准答案、分值都在 `data_value` 中
- **数据准确**：结构化数据比 AI 识别更可靠
- **速度快**：直接读取数据库，无需调用视觉模型
- **成本低**：只需调用文本模型生成测试用例

```

```

### 2.3 生成规则：一题一用例

**核心规则**：每道小题只生成一个测试用例，题目数量 = 测试用例数量

```
示例：10道小题，按场景比例分配

场景配置:
├── 形近干扰 12% → 1道题
├── 等价表达 10% → 1道题
├── 基准测试 20% → 2道题
├── 数字混淆 8%  → 1道题
├── 工整错误 12% → 1道题
└── 其他场景     → 4道题

生成结果: 10个测试用例，每道小题对应1个
```

**场景分配原则**：
1. 优先将「形近干扰」「等价表达」分配给数字类答案（小数、分数）
2. 将「数字混淆」「符号混淆」分配给含数字/符号的答案
3. 选择题（A/B/C/D）分配「工整书写」「潦草书写」「答案错误」
4. 剩余题目分配「基准测试」

### 2.4 AI 生成逻辑

AI 根据题干内容智能生成测试用例：

| 题干特征 | 可生成的测试场景 |
|----------|------------------|
| 答案是数字 (如 8) | 数字混淆 (8→0, 6→0, 9→6) |
| 答案含分数 (如 1/2) | 分数书写测试 |
| 答案含根号 (如 √2) | 根号识别测试 |
| 答案是选项 (如 B) | 选项混淆 (B→D) |
| 答案含变量 (如 x) | 变量混淆 (x→×) |
| 多步骤解答题 | 部分正确测试 |

**示例**：
```
题干: "计算: 3 + 5 = ___"
标准答案: "8"
测试场景: 数字混淆

AI 生成:
- userAnswer: "8" (写得像0)
- fillGuide: "把数字8写得像0，上下两个圈不要连接"
- correct: "yes" (预期AI应该识别为8)
- tags: ["字符混淆", "8/0混淆"]
```

## 3. 测试用例分类体系

### 3.1 一级分类

| 分类 | 说明 | 优先级 |
|------|------|--------|
| 答案正确性测试 | 测试 AI 对正确/错误答案的判断能力 | ⭐⭐⭐ 高 |
| 字符混淆测试 | 测试 AI 对相似字符的识别能力 | ⭐⭐⭐ 高 |
| 数学特定测试 | 测试 AI 对数学符号/公式的识别能力 | ⭐⭐⭐ 高 |
| 书写质量测试 | 测试 AI 对不同书写质量的容忍度 | ⭐⭐ 中 |
| 边界情况测试 | 测试 AI 对特殊情况的处理能力 | ⭐⭐ 中 |
| 学科特定测试 | 其他学科的特殊场景 | ⭐ 低 |

- 测试场景代码自动转换为标签（如 `correct_full` → `完全正确`）

### 8.4 代码兼容处理

```python
def get_item_tags(item):
    """获取题目标签，兼容旧数据"""
    tags = item.get('tags')
    if tags is None:
        # 尝试从 extra_data 获取（兼容旧数据）
        extra_data = item.get('extra_data', {}) or {}
        if isinstance(extra_data, str):
            try:
                extra_data = json.loads(extra_data)
            except:
                extra_data = {}
        tags = extra_data.get('tags', [])
    return tags if isinstance(tags, list) else []
```

## 9. AI Prompt 设计

### 9.1 基准效果生成 Prompt（核心）

**生成规则**：每道小题生成一个测试用例，题目数量 = 测试用例数量，一一对应。

```
你是一个专业的 AI 批改系统测试用例设计师。请为每道小题生成一个测试用例。

## 一、题目信息（共 N 道小题）
{questions_json}

## 二、生成规则：一题一用例

**重要**：每道小题只生成一个测试用例，题目数量 = 测试用例数量

按比例分配测试场景到各题目：
{scene_assignments_json}

分配原则：
1. 优先将「形近干扰」和「等价表达」分配给数字类答案（小数、分数）
2. 将「数字混淆」「符号混淆」分配给含数字/符号的答案

## 三、核心场景说明

### 形近干扰（答案错误，0分）⭐
| 标准答案 | 形近干扰 | 说明 |
|----------|----------|------|
| 37.5 | 375 | 去掉小数点 |
| 0.5 | 5 | 去掉0和小数点 |
| 123 | 12.3 | 添加小数点 |

### 等价表达（答案正确，满分）⭐
| 标准答案 | 等价表达 |
|----------|----------|
| 0.5 | 1/2 或 50% |
| 1/2 | 0.5 或 50% |

## 四、输出格式
返回 JSON 数组，数组长度必须等于题目数量，每个元素对应一道小题。

## 五、注意事项
1. 必须为每道小题生成一个测试用例，不多不少
2. 形近干扰和等价表达优先分配给数字类答案
3. 选择题不适用形近干扰和等价表达
```

### 9.2 场景智能匹配逻辑

AI 会根据答案特征自动匹配适用的测试场景：

| 答案特征 | 可组合的场景 | 生成示例 |
|----------|--------------|----------|
| 纯数字 (8, 36) | 数字混淆 + 答案正确/错误 | ["答案正确", "数字混淆", "8/0混淆"] |
| 含小数 (37.5) | 形近干扰 + 答案错误 ⭐ | ["答案错误", "形近干扰", "小数点移位"] |
| 含分数 (1/2) | 等价表达 + 答案正确 ⭐ | ["答案正确", "等价表达", "分数小数互转"] |
| 可转百分数 (0.5) | 等价表达 + 答案正确 ⭐ | ["答案正确", "等价表达", "百分数转换"] |
| 含变量 (x) | 符号混淆 + 答案正确/错误 | ["答案正确", "符号混淆", "x/×混淆"] |
| 选项字母 (B) | 字母混淆 + 潦草/工整 | ["答案正确", "潦草书写"] |

## 12. 风险与注意事项

### 12.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| AI 生成的测试用例不合理 | 填写指导不可操作 | 支持手动编辑生成结果 |
| 部分题目无 data_value | 无法获取题干内容 | 提示用户该页码暂不支持 |
| 标签统计影响评估性能 | 大数据集评估变慢 | 标签统计异步计算 |

### 12.2 数据兼容性

| 场景 | 处理方式 |
|------|----------|
| 旧数据集无 `tags` 字段 | 视为空数组 `[]`，统计到「无标签」分类 |
| `data_value` 中无 `content` | 使用 `ans` 字段作为参考 |
| `sorce` 字段缺失 | 不生成分数相关测试用例 |

### 12.3 使用建议

1. **选择合适的页码**：优先选择题目类型丰富的页码（含填空、选择、解答）
2. **调整场景比例**：根据测试目的调整，如重点测试数字混淆可提高其比例
3. **填写一致性**：同一套测试用例建议由同一人填写，保持书写风格一致
4. **分批测试**：建议每次生成 20-30 条测试用例，便于管理和填写
